## 一、当前启动位置

已经掌握的调用链：

```text
U-Boot执行Linux启动命令
-> 跳转到ARM64 Image入口`_head`

```

`el2_setup`的调用位置：

```asm
ENTRY(stext)
        bl      preserve_boot_args
        bl      el2_setup
        adrp    x23, __PHYS_OFFSET
        and     x23, x23, MIN_KIMG_ALIGN - 1
        bl      set_cpu_boot_mode_flag
        bl      __create_page_tables
        bl      __cpu_setup

ENDPROC(stext)
```

`bl el2_setup`把下一条指令地址保存到`x30/lr`，然后跳到`el2_setup`。

## 二、异常级别与Hypervisor

ARM64常见异常级别：

| EL | 常见用途 |
|---|---|
| EL0 | 普通用户程序 |
| EL1 | Linux Kernel |
| EL2 | Hypervisor/虚拟化宿主 |
| EL3 | Secure Monitor/BL31 |

EL不是进程优先级，而是CPU权限状态。低异常级别不能自行提升到更高异常级别。

Hypervisor是运行于EL2的虚拟机管理程序，负责虚拟CPU、Stage-2地址转换、虚拟中断与Timer，并可通过EL2寄存器规定EL1操作是否Trap到EL2。常见实现包括KVM、Xen和Jailhouse。

## 三、`el2_setup`的核心目标

`el2_setup`并非只设置`SCTLR_EL1/EL2`。它的目标是：

1. 检测CPU进入Kernel时位于EL1还是EL2。
2. 初始化对应异常级别的系统控制状态和端序。
3. 从EL2进入时，配置EL2对Timer、GIC、PMU、SPE、FP/SIMD/SVE及Stage-2等功能的监管状态。
4. 根据VHE决定宿主Kernel留在EL2，还是通过`eret`进入EL1。
5. 返回CPU最初进入Kernel时的异常级别。

它不负责创建页表、正式开启MMU、解析DTB或启动调度器。

## 四、真实源码主分支

源码位置约为`head.S:478-639`。

### 1. 判断当前异常级别

```asm
ENTRY(el2_setup)
        msr     SPsel, #1
        mrs     x0, CurrentEL
        cmp     x0, #CurrentEL_EL2
        b.eq    1f
```

- `SPsel=1`：使用当前异常级别对应的栈指针。
- `mrs x0, CurrentEL`：读取当前异常级别。
- 如果当前是EL2，跳到局部标签`1:`；否则走EL1路径。
- `1f`表示向前寻找最近的`1:`，`1b`表示向后寻找。

### 2. 从EL1进入

```asm
        mov_q   x0, (SCTLR_EL1_RES1 | ENDIAN_SET_EL1)
        msr     sctlr_el1, x0
        mov     w0, #BOOT_CPU_MODE_EL1
        isb
        ret
```

Kernel只能配置EL1及以下，无法写`CPTR_EL2`、`HCR_EL2`等EL2寄存器。EL2环境必须由前级固件或已有Hypervisor提供。

Linux后续只会配置自己有权限控制的EL1寄存器，例如`CPACR_EL1`、`VBAR_EL1`、`SCTLR_EL1`、`TCR_EL1`和页表基址，不会在运行一段时间后自行获得EL2权限。

### 3. 从EL2进入并检测VHE

```asm
1:      mov_q   x0, (SCTLR_EL2_RES1 | ENDIAN_SET_EL2)
        msr     sctlr_el2, x0

#ifdef CONFIG_ARM64_VHE
        mrs     x2, id_aa64mmfr1_el1
        ubfx    x2, x2, #8, #4
#else
        mov     x2, xzr
#endif
```

使用VHE必须同时满足：

```text
Kernel编译启用CONFIG_ARM64_VHE
+ CPU硬件支持VHE
```

约定：

```text
x2 == 0：不使用VHE
x2 != 0：使用VHE
```

### 4. 设置EL2 Host控制

```asm
        mov_q   x0, HCR_HOST_NVHE_FLAGS
        cbz     x2, set_hcr
        mov_q   x0, HCR_HOST_VHE_FLAGS
set_hcr:
        msr     hcr_el2, x0
        isb
```

`HCR_EL2`控制EL2虚拟化和Host语义。`cbz`只负责条件跳转，本身不配置Timer、GIC或其他硬件。

源码中间真实存在Timer、GIC、PMU、SPE、CPU标识和Stage-2等配置；此前笔记中的“此处继续配置”只是讲解时的省略，不是源码指令。

### 5. Timer、GIC与Stage-2的目的

EL2是EL1的监管层，可以规定EL1访问某些功能时直接执行或Trap到EL2。Linux从EL2降到EL1前，必须趁仍有EL2权限整理这些规则。

典型操作：

```asm
/* 允许EL1访问物理Timer */
mrs     x0, cnthctl_el2
orr     x0, x0, #3
msr     cnthctl_el2, x0

/* 清除虚拟Timer偏移 */
msr     cntvoff_el2, xzr

/* 清除Stage-2转换表基址 */
msr     vttbr_el2, xzr
```

这些操作不是让EL1主动访问EL2寄存器，而是EL2提前设置未来EL1的运行规则。

## 五、`CPTR_EL2`、协处理器和SVE

非VHE路径中：

```asm
mov     x0, #0x33ff
msr     cptr_el2, x0

mrs     x1, id_aa64pfr0_el1
ubfx    x1, x1, #ID_AA64PFR0_SVE_SHIFT, #4
cbz     x1, 7f

bic     x0, x0, #CPTR_EL2_TZ
msr     cptr_el2, x0
isb
mov     x1, #ZCR_ELx_LEN_MASK
msr_s   SYS_ZCR_EL2, x1
```

`CPTR_EL2`控制EL1/EL0使用FP、SIMD、SVE等能力时是否Trap到EL2。

核心区别：

```text
错误理解：设置CPTR_EL2是为了让EL1访问EL2寄存器。

正确理解：EL2设置CPTR_EL2，规定未来EL1执行协处理器/SVE操作时
          是直接执行，还是被CPU硬件拦截到EL2。
```

从EL1直接进入时，Linux无权设置`CPTR_EL2`；该规则由前级固件或外部Hypervisor负责。从EL2进入并准备降到EL1时，Linux当前拥有EL2，必须先清理不需要的Trap，否则进入EL1后无法回头修改EL2状态。

`SVC`与`CPTR_EL2`无关：

```text
SVC：EL0请求EL1系统调用服务
HVC：请求EL2 Hypervisor服务
SMC：请求EL3 Secure Monitor服务
```

EL0执行`SVC`进入EL1，主要依赖`VBAR_EL1`、`ELR_EL1`、`SPSR_EL1`和Linux系统调用入口。

## 六、VHE的准确含义

VHE全称Virtualization Host Extensions，是ARM CPU硬件提供的虚拟化宿主扩展，不是map文件，也不是软件寄存器映射表。

工作方式：

```text
CPU硬件支持VHE
-> Linux读取CPU能力寄存器
-> Kernel启用CONFIG_ARM64_VHE
-> Linux设置HCR_EL2.E2H等控制位
-> CPU按EL2 Host语义解释架构规定的寄存器访问
```

VHE允许宿主Kernel留在EL2，并通过硬件定义的系统寄存器别名/重定向语义复用大量EL1风格代码。例如对架构规定支持Host别名的寄存器访问，源码可能仍使用`*_EL1`形式，但CPU在EL2 Host模式下按对应的宿主EL2语义处理。

不能表述为“Kernel代码自动转换成EL2代码”；准确说法是：同一批指令由CPU硬件按照VHE Host语义解释。

## 七、VHE与非VHE两条EL2路径

### VHE路径

```text
从EL2进入
-> 配置EL2 Host环境
-> Kernel留在EL2
-> 普通宿主CPU状态后续通过VHE兼容路径配置
```

宿主不运行于EL1，因此`install_el2_stub`不需要配置“宿主EL1使用协处理器时是否Trap到EL2”。未来运行Guest时，KVM仍会单独配置Guest虚拟EL1的Trap策略。

### 非VHE路径

```text
从EL2进入
-> 配置EL2对未来EL1的Timer/GIC/协处理器等监管规则
-> 初始化必要EL1状态
-> 安装EL2 stub
-> 设置SPSR_EL2和ELR_EL2
-> eret进入EL1
```

“Linux在EL1时一般不会发生非预期EL2 Trap”是正确配置`CPTR_EL2`等寄存器后的结果，不是EL1天然不会Trap。

## 八、为什么设置`VBAR_EL2`

非VHE Kernel主体虽然进入EL1，但EL2仍然存在。未来可能因`HVC`、意外Trap或KVM操作进入EL2，因此源码执行：

```asm
adr_l   x0, __hyp_stub_vectors
msr     vbar_el2, x0
```

`VBAR_EL2`保存EL2异常向量表基址。`__hyp_stub_vectors`提供最小安全入口，避免EL2异常发生时跳到未知地址。它不只是处理普通中断，而是整个EL2异常向量入口。

## 九、`ret`与`eret`

普通返回：

```text
bl el2_setup
-> x30/lr = 返回地址

ret
-> PC = x30/lr
-> 异常级别和PSTATE不变
```

异常返回：

```asm
msr spsr_el2, x0
msr elr_el2, lr
eret
```

```text
eret
-> PC = ELR_EL2
-> PSTATE = SPSR_EL2
-> 可完成EL2到EL1的状态切换
```

`eret`不直接读取`lr`，因此先把普通调用返回地址从`lr`复制到`ELR_EL2`。`SPSR_EL2`描述返回后的异常级别、栈模式和中断屏蔽状态。

## 十、为什么非VHE仍返回`BOOT_CPU_MODE_EL2`

```asm
mov     w0, #BOOT_CPU_MODE_EL2
eret
```

该值记录CPU最初进入Linux Kernel入口时的异常级别，不记录`el2_setup`结束后的当前级别。

```text
进入el2_setup：EL2
结束el2_setup：通过eret运行于EL1
启动模式记录：BOOT_CPU_MODE_EL2
```

它类似记录“出发地”，而不是当前位置。后续`set_cpu_boot_mode_flag`将该值保存到`__boot_cpu_mode`，供Kernel判断启动模式和虚拟化能力。

## 十一、完整控制流

```text
el2_setup
├── CurrentEL == EL1
│   ├── 初始化SCTLR_EL1和端序
│   ├── w0 = BOOT_CPU_MODE_EL1
│   └── ret，继续在EL1
│
└── CurrentEL == EL2
    ├── 初始化SCTLR_EL2
    ├── 检测Kernel配置和CPU VHE能力
    ├── 配置HCR_EL2、Timer、GIC、PMU、SPE、Stage-2等
    │
    ├── 使用VHE
    │   ├── w0 = BOOT_CPU_MODE_EL2
    │   └── ret，继续在EL2 Host模式
    │
    └── 不使用VHE
        ├── 初始化必要EL1状态
        ├── 配置CPTR_EL2等EL1监管规则
        ├── VBAR_EL2 = __hyp_stub_vectors
        ├── SPSR_EL2 = EL1h目标状态
        ├── ELR_EL2 = lr
        ├── w0 = BOOT_CPU_MODE_EL2
        └── eret进入EL1并返回stext后续代码
```

## 十二、今日八股考核与标准答案

### 1. `el2_setup()`解决什么问题？

检测CPU进入Kernel时位于EL1还是EL2，初始化对应控制状态；从EL2进入时还要配置EL2对Timer、GIC、PMU、协处理器、SVE和Stage-2等功能的监管规则，并根据VHE决定留在EL2或切换到EL1，最后返回初始启动级别。

### 2. 从EL1进入为何不配置`CPTR_EL2`？

因为EL1无权访问EL2系统寄存器，后续也不会自行获得EL2权限。EL2 Trap规则必须由前级固件或已有Hypervisor提前配置。

### 3. 从EL2进入、非VHE为何必须先配置EL2再降到EL1？

EL2可以监管EL1，而Kernel降到EL1后无法再修改EL2寄存器。因此必须趁仍在EL2时清理遗留状态、配置Trap和访问规则、安装最小异常向量，再进入EL1。

### 4. VHE是什么，为什么Kernel能留在EL2？

VHE是ARM Virtualization Host Extensions。Linux检测硬件能力并设置`HCR_EL2.E2H`等位后，CPU为架构规定的系统寄存器访问提供EL2 Host语义，使大量EL1风格Kernel代码可以复用，宿主Kernel因此能够高效运行在EL2。

### 5. `ret`与`eret`有什么区别？

`ret`通常从`x30/lr`恢复PC，异常级别和PSTATE不变；`eret`从`ELR_EL2`恢复PC、从`SPSR_EL2`恢复处理器状态，可以完成EL2到EL1切换。

### 6. 非VHE为什么设置`VBAR_EL2`？

主体进入EL1后仍可能因HVC、意外Trap或后续KVM操作进入EL2，因此需要让EL2异常跳到合法的`__hyp_stub_vectors`，避免进入未知地址。

### 7. `BOOT_CPU_MODE_EL2`记录什么？

记录启动CPU最初进入Linux Kernel入口时处于EL2，不表示`el2_setup`结束后仍位于EL2。

### 8. `CPTR_EL2`设置的是什么？

设置EL2是否拦截EL1/EL0对FP、SIMD、SVE等协处理器功能的使用。它不是让EL1访问EL2寄存器，而是由EL2定义低异常级别操作的Trap规则。

### 9. 从EL1进入时，应用执行`SVC`怎么办？

`SVC`与`CPTR_EL2`无关。EL0执行`SVC`进入EL1的系统调用异常入口，依赖`VBAR_EL1`、`ELR_EL1`、`SPSR_EL1`和Linux系统调用分发。Linux后续会配置自己的EL1异常环境。

### 10. 从EL1进入是否意味着以后完全不会到EL2？

Linux不会自行升级到EL2，也不能直接访问EL2系统寄存器；但若EL2由外部Hypervisor管理，Linux操作可能被其Trap到EL2，Linux也可通过`HVC`请求EL2服务。Linux仍不获得EL2控制权。

### 11. 为什么非VHE配置协处理器/SVE，VHE却不走这一段？

非VHE宿主即将进入EL1，必须提前设置未来EL1的Trap规则；VHE宿主留在EL2，不存在宿主EL1到EL2的Trap问题，相关EL2 Host状态由后续VHE兼容路径完成。

### 12. VHE寄存器别名由软件map完成吗？

不是。别名和重定向语义由ARM CPU硬件实现；Linux负责检测能力并设置`HCR_EL2.E2H`等位，开启后硬件自动按VHE Host语义解释相关系统寄存器指令。

## 附录：项目内核中的完整原始源码

来源：

```text
/home/liu/linux_driver/project/vendor/sdk/kernel/arch/arm64/kernel/head.S
原始行号：478-654
```

以下代码保留了`el2_setup`中此前讲解时省略的Timer、GIC、PMU、SPE、LORegions和Stage-2配置，以及紧随其后的`set_cpu_boot_mode_flag`。

```asm
ENTRY(el2_setup)
	msr	SPsel, #1			// We want to use SP_EL{1,2}
	mrs	x0, CurrentEL
	cmp	x0, #CurrentEL_EL2
	b.eq	1f
	mov_q	x0, (SCTLR_EL1_RES1 | ENDIAN_SET_EL1)
	msr	sctlr_el1, x0
	mov	w0, #BOOT_CPU_MODE_EL1		// This cpu booted in EL1
	isb
	ret

1:	mov_q	x0, (SCTLR_EL2_RES1 | ENDIAN_SET_EL2)
	msr	sctlr_el2, x0

#ifdef CONFIG_ARM64_VHE
	/*
	 * Check for VHE being present. For the rest of the EL2 setup,
	 * x2 being non-zero indicates that we do have VHE, and that the
	 * kernel is intended to run at EL2.
	 */
	mrs	x2, id_aa64mmfr1_el1
	ubfx	x2, x2, #8, #4
#else
	mov	x2, xzr
#endif

	/* Hyp configuration. */
	mov_q	x0, HCR_HOST_NVHE_FLAGS
	cbz	x2, set_hcr
	mov_q	x0, HCR_HOST_VHE_FLAGS
set_hcr:
	msr	hcr_el2, x0
	isb

	/*
	 * Allow Non-secure EL1 and EL0 to access physical timer and counter.
	 * This is not necessary for VHE, since the host kernel runs in EL2,
	 * and EL0 accesses are configured in the later stage of boot process.
	 * Note that when HCR_EL2.E2H == 1, CNTHCTL_EL2 has the same bit layout
	 * as CNTKCTL_EL1, and CNTKCTL_EL1 accessing instructions are redefined
	 * to access CNTHCTL_EL2. This allows the kernel designed to run at EL1
	 * to transparently mess with the EL0 bits via CNTKCTL_EL1 access in
	 * EL2.
	 */
	cbnz	x2, 1f
	mrs	x0, cnthctl_el2
	orr	x0, x0, #3			// Enable EL1 physical timers
	msr	cnthctl_el2, x0
1:
	msr	cntvoff_el2, xzr		// Clear virtual offset

#ifdef CONFIG_ARM_GIC_V3
	/* GICv3 system register access */
	mrs	x0, id_aa64pfr0_el1
	ubfx	x0, x0, #24, #4
	cbz	x0, 3f

	mrs_s	x0, SYS_ICC_SRE_EL2
	orr	x0, x0, #ICC_SRE_EL2_SRE	// Set ICC_SRE_EL2.SRE==1
	orr	x0, x0, #ICC_SRE_EL2_ENABLE	// Set ICC_SRE_EL2.Enable==1
	msr_s	SYS_ICC_SRE_EL2, x0
	isb					// Make sure SRE is now set
	mrs_s	x0, SYS_ICC_SRE_EL2		// Read SRE back,
	tbz	x0, #0, 3f			// and check that it sticks
	msr_s	SYS_ICH_HCR_EL2, xzr		// Reset ICC_HCR_EL2 to defaults

3:
#endif

	/* Populate ID registers. */
	mrs	x0, midr_el1
	mrs	x1, mpidr_el1
	msr	vpidr_el2, x0
	msr	vmpidr_el2, x1

#ifdef CONFIG_COMPAT
	msr	hstr_el2, xzr			// Disable CP15 traps to EL2
#endif

	/* EL2 debug */
	mrs	x1, id_aa64dfr0_el1		// Check ID_AA64DFR0_EL1 PMUVer
	sbfx	x0, x1, #8, #4
	cmp	x0, #1
	b.lt	4f				// Skip if no PMU present
	mrs	x0, pmcr_el0			// Disable debug access traps
	ubfx	x0, x0, #11, #5		// to EL2 and allow access to
4:
	csel	x3, xzr, x0, lt		// all PMU counters from EL1

	/* Statistical profiling */
	ubfx	x0, x1, #32, #4		// Check ID_AA64DFR0_EL1 PMSVer
	cbz	x0, 7f				// Skip if SPE not present
	cbnz	x2, 6f				// VHE?
	mrs_s	x4, SYS_PMBIDR_EL1		// If SPE available at EL2,
	and	x4, x4, #(1 << SYS_PMBIDR_EL1_P_SHIFT)
	cbnz	x4, 5f				// then permit sampling of physical
	mov	x4, #(1 << SYS_PMSCR_EL2_PCT_SHIFT | \
		      1 << SYS_PMSCR_EL2_PA_SHIFT)
	msr_s	SYS_PMSCR_EL2, x4		// addresses and physical counter
5:
	mov	x1, #(MDCR_EL2_E2PB_MASK << MDCR_EL2_E2PB_SHIFT)
	orr	x3, x3, x1			// If we don't have VHE, then
	b	7f				// use EL1&0 translation.
6:						// For VHE, use EL2 translation
	orr	x3, x3, #MDCR_EL2_TPMS		// and disable access from EL1
7:
	msr	mdcr_el2, x3			// Configure debug traps

	/* LORegions */
	mrs	x1, id_aa64mmfr1_el1
	ubfx	x0, x1, #ID_AA64MMFR1_LOR_SHIFT, 4
	cbz	x0, 1f
	msr_s	SYS_LORC_EL1, xzr
1:

	/* Stage-2 translation */
	msr	vttbr_el2, xzr

	cbz	x2, install_el2_stub

	mov	w0, #BOOT_CPU_MODE_EL2		// This CPU booted in EL2
	isb
	ret

install_el2_stub:
	/*
	 * When VHE is not in use, early init of EL2 and EL1 needs to be
	 * done here.
	 * When VHE _is_ in use, EL1 will not be used in the host and
	 * requires no configuration, and all non-hyp-specific EL2 setup
	 * will be done via the _EL1 system register aliases in __cpu_setup.
	 */
	mov_q	x0, (SCTLR_EL1_RES1 | ENDIAN_SET_EL1)
	msr	sctlr_el1, x0

	/* Coprocessor traps. */
	mov	x0, #0x33ff
	msr	cptr_el2, x0			// Disable copro. traps to EL2

	/* SVE register access */
	mrs	x1, id_aa64pfr0_el1
	ubfx	x1, x1, #ID_AA64PFR0_SVE_SHIFT, #4
	cbz	x1, 7f

	bic	x0, x0, #CPTR_EL2_TZ		// Also disable SVE traps
	msr	cptr_el2, x0			// Disable copro. traps to EL2
	isb
	mov	x1, #ZCR_ELx_LEN_MASK		// SVE: Enable full vector
	msr_s	SYS_ZCR_EL2, x1			// length for EL1.

	/* Hypervisor stub */
7:	adr_l	x0, __hyp_stub_vectors
	msr	vbar_el2, x0

	/* spsr */
	mov	x0, #(PSR_F_BIT | PSR_I_BIT | PSR_A_BIT | PSR_D_BIT |\
		      PSR_MODE_EL1h)
	msr	spsr_el2, x0
	msr	elr_el2, lr
	mov	w0, #BOOT_CPU_MODE_EL2		// This CPU booted in EL2
	eret
ENDPROC(el2_setup)

/*
 * Sets the __boot_cpu_mode flag depending on the CPU boot mode passed
 * in w0. See arch/arm64/include/asm/virt.h for more info.
 */
set_cpu_boot_mode_flag:
	adr_l	x1, __boot_cpu_mode
	cmp	w0, #BOOT_CPU_MODE_EL2
	b.ne	1f
	add	x1, x1, #4
1:	str	w0, [x1]			// This CPU has booted in EL1
	dmb	sy
	dc	ivac, x1			// Invalidate potentially stale cache line
	ret
ENDPROC(set_cpu_boot_mode_flag)
```
