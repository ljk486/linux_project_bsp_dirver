# Board peripheral smoke test

Date: 2026-10-17
Board: LubanCat 2 RK3568
Serial: COM9, 1500000-8-N-1
Kernel: 4.19.232

## Root filesystem capacity

After installing `linux-image-4.19.232`, the root filesystem was full because the ext4 filesystem inside `rootfs.img` was about 1.3 GiB while `/dev/mmcblk0p3` was about 7.2 GiB.

Before resize:

```text
/dev/root  1.4G  1.3G  0  100% /
```

The partition size reported by `blockdev` was 7,700,725,248 bytes. The filesystem was expanded online:

```bash
resize2fs /dev/mmcblk0p3
```

After resize:

```text
/dev/root  7.1G  1.3G  5.5G  19% /
```

No files were deleted. The boot partition remains mounted at `/mnt/boot` with about 55 MiB available.

## Network

```text
lo    UNKNOWN  127.0.0.1/8
eth0  DOWN     ce:a3:70:5e:bb:a0  NO-CARRIER
usb0  DOWN     8e:ae:37:6d:a8:68  NO-CARRIER
```

The Ethernet driver probed successfully. `ethtool eth0` reports support for 10/100/1000baseT and auto-negotiation, but:

```text
Link detected: no
```

No physical Ethernet link was present during the test.

## USB

`lsusb` showed the six Linux Foundation root hubs. No external USB device was connected.

Kernel logs show the USB gadget/controller path initialized, with repeated non-fatal configfs gadget messages:

```text
Config b/1 of rockchip needs at least one function.
configfs-gadget fcc00000.dwc3: failed to start rockchip: -22
```

This is a gadget configuration issue, not evidence that the USB host controller failed.

## V4L2 / Camera

No video or media devices were present:

```text
/dev/video*: not found
/dev/media*: not found
v4l2-ctl --list-devices: Cannot open device /dev/video0
```

This is consistent with no camera sensor or capture pipeline being active in the current setup. Camera validation remains pending.

## DRM/KMS

The DRM devices exist:

```text
/dev/dri/card0
/dev/dri/renderD128
```

`modetest -c -p -e` enumerated:

- HDMI-A-1 connector
- Virtual and TMDS encoders
- One CRTC
- Multiple planes
- RGB formats including XR24, AR24, XB24, AB24, RG16 and BG16
- Overlay/cluster planes with NV12 and YUV formats

Current HDMI state:

```text
HDMI-A-1 disconnected
modes: 0
```

No display was connected during the test, so no modesetting or page-flip test was attempted.

## Current conclusion

The self-built baseline now has:

- Kernel modules installed and loadable
- Root filesystem expanded to the full eMMC rootfs partition
- Ethernet, USB, I2C, GPIO and DRM device paths enumerated
- No active camera capture device yet

Remaining hardware-dependent checks:

- Connect Ethernet and verify link/address/traffic
- Insert a USB device and verify enumeration/storage
- Connect or identify an I2C peripheral before using `i2cdetect`
- Identify the intended GPIO test line before changing output state
- Connect HDMI and run a display modeset test
- Connect the target camera and validate V4L2/media nodes
